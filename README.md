# Hype Swarm

A game built in Unity 6 (`6000.6.0f1`) on the Universal Render Pipeline.

## Requirements

- Unity `6000.6.0f1` — install it with [Unity Hub](https://unity.com/download), or from the Unity CLI:
  ```
  unity install 6000.6.0f1
  ```

## Getting started

```
git clone https://github.com/CodeINN95612/HypeSwarm.git
```

Open the cloned folder in Unity Hub, or from the CLI:

```
unity open HypeSwarm
```

Unity regenerates `Library/`, the solution files and `UserSettings/` on first import, so they are not tracked here.

## Prototype arena

`Assets/Scenes/Prototype.unity` is the testbed: a floor on a four-metre grid, seeded cover, a ring of
training dummies, and up to five champions. Press Play and you are hosting; a champion spawns and the
camera takes it.

| | |
|---|---|
| Move | `WASD` or the arrow keys |
| Aim | mouse — independent of movement |
| Primary — Flame Lance | left mouse, held. Roots for a quarter second each cast |
| Secondary — Ember Ward | `E` or `Q`. Shields, and slows what is close |
| Mobility — Searing Dash | `Space` or right mouse. Two charges |
| Ultimate — Crucible | hold `R` to channel, let go to detonate |
| Network panel | `F1` |

The five slots come from the **Pyre** champion asset, not from code: the panel under `F1` lists them
with their cooldowns and cast costs, and shows the health of whatever hostile is nearest so damage
landing on a dummy is visible from inside your own champion.

Feel is tuned on the **Champion** prefab, under Movement. Those fields are live during Play, which
is the point of them being there; when a number is right, copy it back with the component's context
menu before leaving Play Mode.

The scene and the champion prefab are generated by **Hype Swarm → Build Prototype Arena**, not
authored by hand — the arrangement lives in `PrototypeArenaBuilder.cs` where it can be diffed.
Rebuilding replaces both assets.

Pyre's five abilities and the effect steps behind them come from **Hype Swarm → Build Prototype
Champion**, for the same reason. Nothing in that script is code the ability system runs: every asset
it writes is data that could have been filled in by hand in the inspector, which is the point — a new
ability is a new asset, not a new script.

## Multiplayer

Mirror, with the transport chosen at runtime and never compiled in: **Steam** (FizzySteamworks) when
a Steam client is running, **direct** (KCP over UDP) otherwise. Movement is client-authoritative —
each player's own machine decides where their champion is.

Both are in `Assets/Mirror`, along with Steamworks.NET, and are committed rather than fetched. The
`steam_appid.txt` at the repo root is Valve's public test id (480) and is a development stand-in
until the game has one of its own.

### Playing together

Press `F1` in Play Mode for the network panel. **Host on Steam** creates a friends-only lobby and
**Invite friends…** opens Steam's own invite overlay; accepting an invite connects the friend with
no address to exchange. Without Steam, one player hosts and the others type their address.

### Testing five players on one machine

```
Hype Swarm → Network → Build Test Player          (once, and after any code change)
Hype Swarm → Network → Launch 4 Test Clients      (with the Editor already playing)
```

The clients connect to the Editor on loopback, so this exercises spawning, ownership, the roster and
join/leave, but not latency. Mirror's `LatencySimulation` transport covers that, and neither replaces
actually running it on five machines.

### Launch arguments

Every one of these is read by `NetworkLaunchOptions`, and a bad value produces a warning rather than
silence.

| | |
|---|---|
| `-hypeswarm-connect <host[:port]>` | connect as a client |
| `-hypeswarm-host` / `-hypeswarm-server` | host with a local player / serve without one |
| `-hypeswarm-offline` | load the scene and start nothing |
| `-hypeswarm-transport <steam\|direct>` | override the automatic choice |
| `-hypeswarm-port <n>` | default 7777 |
| `-hypeswarm-name <text>` | name in the lobby roster |

With no arguments a process hosts; `-batchmode` makes it a dedicated server, and a headless process
never uses Steam because there is no Steam client attached to it.

## Tests

EditMode tests live in `Assets/Tests/EditMode` and run in a few seconds. Open **Window → General →
Test Runner** in the Editor, or from the CLI with the Editor closed:

```
unity test --mode EditMode
```

What belongs in a test — and what deliberately does not — is set out in [CLAUDE.md](CLAUDE.md).

## Scene merging

Unity ships a YAML-aware merge tool that resolves conflicts in scenes and prefabs far better than a plain text merge. `.gitattributes` already routes those file types to it; register the driver once per clone:

```
git config merge.unityyamlmerge.name "Unity SmartMerge"
git config merge.unityyamlmerge.driver '"C:/Program Files/Unity/Hub/Editor/6000.6.0f1/Editor/Data/Tools/UnityYAMLMerge.exe" merge -p "$BASE" "$REMOTE" "$LOCAL" "$MERGED"'
```
